# 四季夏目 · 酒馆联动包（Natsume TTS × SillyTavern）

把本机的 **Natsume TTS**（GPT-SoVITS，四季夏目音色）接到 **SillyTavern**，让她在酒馆里
**说日文、出中文对照、按情绪换语气、按好感度推进关系**，并给拟声词单独配音。

> 这套东西不新造任何模型：语音走 `Natsume_TTS` 已有的 9880 服务，说话内容由酒馆里的模型生成。
> 本目录只做「接线」和「协议」。

---

## 1. 这套东西由什么组成

| 部件 | 位置 | 作用 |
|---|---|---|
| **TTS 服务** | `Natsume_TTS/_run/infer_api.py`（9880） | 合成日文语音；14 个「表演角度」；关系阶段与场合的状态机 |
| **酒馆扩展** | `st-integration/extension/`（软链到酒馆 `data/default-user/extensions/natsume-tts`） | 解析协议标签、逐句合成播放、好感度计分、把状态注入生成提示 |
| **角色卡** | `st-integration/card/四季夏目.png` | 人设 + 输出协议 + 好感度四阶段 + 世界书；已导入酒馆 |
| **工具** | `st-integration/tools/` | 打包角色卡（纯标准库）、文本层回归测试 |
| **素材** | `../../Work/stellacafe-assets/` | 官方立绘 / Steam 截图的原始件与来源清单 |

用 `tools/make_card.py` 打包，改内容不用回 Node 侧。

## 2. 起服务

两个服务，都在本机跑：

```bash
# ① TTS（9880）—— 必须监听 0.0.0.0，否则局域网里的浏览器请求不到它
cd $HOME/Code/Harness/Natsume_TTS
nohup _mac/run_infer_api.sh --host 0.0.0.0 --port 9880 --preload > /tmp/natsume_tts.log 2>&1 &

# ② 酒馆（8000）
cd $HOME/Code/SillyTavern
PATH="/opt/homebrew/bin:$PATH" nohup node server.js > /tmp/sillytavern.log 2>&1 &
```

> ⚠️ 这台机器上 `node` 默认指向 HarnessForge 的 Electron shim，**必须把 `/opt/homebrew/bin` 放到 PATH 前面**，
> 否则 `npm`/`node` 都不是你以为的那个。

自检：

```bash
curl -s http://127.0.0.1:9880/health            # ready: true
curl -s http://127.0.0.1:9880/speakers | head   # 14 个声音
curl -s -u harness:<密码> http://192.168.1.238:8000/   # 200
```

### 关于 TTS 服务也暴露在局域网上

`--host 0.0.0.0` 是**故意的**：局域网设备的浏览器要能直接请求它来取音频；
它本身**没有任何鉴权**，同网段的人都能拿它合成语音（拿不到你的聊天记录）。
不接受的话两个选择：

* 只在本机用 → TTS 去掉 `--host 0.0.0.0`（回 127.0.0.1），但局域网设备就没声音了；
* 或者给 9880 套一层反代加鉴权。

## 5. 协议：她怎么说话

角色卡的 `system_prompt` 已经写死这套协议，这里只做速查。

```
……別に。あんたを待ってたわけじゃない。
[声:tsukkomi][拟声:ふぅ][译:……没什么。我又不是在等你。]
```

| 标签 | 含义 | 处理 |
|---|---|---|
| `[声:x]` | 情绪角度 | 选哪个音色参考（见下表） |
| `[拟声:x]` | 拟声词 | **单独合成一小段**，用专用角度 |
| `[译:x]` | 中文对照 | 显示、不发音 |
| `[场景:x]` | 切换场合 | 同步给 TTS 服务，影响语气上限 |
| `[心动]` | 她被打动 | 好感度 +2 |

**长度约束（硬）**：一条回复 1~2 句，**每句 5~35 个日文字符**。
实测合成耗时 ≈ 0.17 s × 字数：

| 字数 | 音频时长 | 墙钟耗时 |
|---|---|---|
| 20 | 2.9 s | 3.4 s |
| 49 | 8.3 s | 9.2 s |
| 79 | 13.9 s | 15.2 s |

扩展在渲染层做二次保险：默认每段上限 60 字、单条最多 3 句，
超了就在句读处截断并挂一个「超长已截 N 字」的提示——**提示出现就说明模型没守规矩**。

### 音色角度（服务端 `_run/st_voices.py`，14 个）

`neutral` 默认 · `cold` 冷淡质问 · `tsukkomi` 冷静吐槽 · `calm` 平静叙述 ·
`question` 疑问 · `warm` 温柔泄露 · `shy` 害羞掩饰 · `low` 独处低落 · `murmur` 小声嘟囔

拟声专用（扩展自动选）：`natsume-sigh` 叹气 · `natsume-laugh` 轻笑 ·
`natsume-nod` 应声 · `natsume-surprise` 短促一惊 · `natsume-question` 招呼

> 拟声实测：`はぁ` 1.22s / `ふふっ` 1.06s / `うん` 0.86s / `あっ` 1.18s / `んっ` 0.82s。
> **纯标点（如「……」）不能合成**，服务端会返回 400——扩展按「无日文字符」直接跳过，不会报错。

## 6. 节奏：先出声、后出字

**问题**：模型出字比语音合成快得多（合成一句要 1.5~4 秒），用户会先读完文字、再干等声音，
读和听完全对不上拍子。

**做法**：一条新消息刚渲染出来就先藏起来 → 合成 → **音频真的开始出声的那一刻**再放出来。

```
生成结束 → 消息隐藏（只留一个「语音合成中…」的小圆点）
         → 逐段合成（1~4 秒）
         → 第一段音频开始播 ──► 文字同时出现
         → 继续播剩下的段
```

两个细节：

* **短消息不藏**。合成也就 1.5 秒左右，藏了反而像卡顿，所以只在「预计合成 ≥ 3 秒」时才藏
  （阈值：日文字符数 ≥ 30，或按实测公式 `0.19s × 字数 + 0.8s` 算出来 ≥ 3 秒）。
* **只在音频真出声时放字**。挂的是 `<audio>` 的 `playing` 事件，不是 `play()` 调用 ——
  少这一点差别，文字就会比声音早一两百毫秒。
* **45 秒兜底**：任何异常路径（TTS 挂了、播放被浏览器拦截）都会让文字自己出现，
  不会出现「消息永远不出现」的坑。出错时也会显式放出来。

设置面板里两个开关：

| 控件 | 默认 | 说明 |
|---|---|---|
| 先出声后出字 | 开 | 关掉就回到「文字立刻出现、声音随后跟上」 |
| 显示时机 | 音频一响就显示 | 另一选项是「整条播完再显示」（适合想完全听完再读的场合） |

> 副作用（故意的）：播放是**串行**的。上一条还在播/还在合成时，下一条不会插进来 ——
> 这样「听」和「读」共用同一条时间线。想打断就点消息上的 🔊。

## 7. 好感度

0~100，四阶段与门槛：

| 点数 | 阶段 | 语气变化 |
|---|---|---|
| 0 | 初识 | 客气、疏离、简短 |
| 20 | 暧昧初期 | 在意但绝不承认；掩饰 + 吐槽 |
| 50 | 确认关系 | 关心变直接，仍简短、不肉麻 |
| 80 | 亲密期 | 允许温柔与轻微撒娇；底色仍冷 |

**计分规则**（都印在扩展面板上，不做暗箱）：

* `+1` 每轮对话（60 秒内连发只算一次）
* `+1` 用户消息 ≥ 12 字（认真说话）
* `+1` 命中礼貌/关心词；`-1` 命中冒犯词
* `+2` 模型打了 `[心动]` 时

**关键设计**：关系阶段是**双写一致**的——

* 扩展把阶段 POST 给 TTS 服务（`/state`），服务端据此**夹紧**语音条件上限
  （初识时温暖度 ≤ 0.20、亲密度 ≤ 0.10；外层冷淡度任何阶段不低于 0.50 的人设地板）；
* 同时把 `<natsume_state>` 注入生成提示（追加在最后一条消息上，权重最高），
  让模型知道此刻该冷到什么程度。

阶段是**有上限**的：到「初识」就说不出亲密期的话——不是靠模型自觉，是服务端会夹紧。

## 8. 常见问题

**Q：扩展装了但「看不到」它。**
这不是安装失败，是**位置问题**——酒馆里第三方扩展**不在**「Manage extensions / 管理扩展」那个列表里
（那里面只有内置扩展），它把自己的面板插进**「扩展」主面板的底部**。

依次点：

1. 顶部栏的 **扩展** 图标（方块/拼图，快捷键在 UI 里有提示）——这就是「扩展」主面板；
2. 面板里找到折叠条 **「四季夏目 · 语音与好感度」**，点开它；
3. 展开后就是本扩展的全部控件（好感度、场合、端点、节奏、检测连接、测试语音…）。

> 这个面板本身**不列第三方扩展**，所以「看不到」是正常的，不代表没装上。
> 想确认装没装：看页面**右下角的常驻小徽章**（见下）。

**Q：TTS 到底上线没有？**
页面右下角有个常驻小徽章，一眼可答：

| 颜色 | 含义 |
|---|---|
| 🟢 绿 | 在线，且模型已加载 |
| 🟣 粉（呼吸） | 正在合成 / 正在播放 |
| 🔴 红 | 连不上（点它可以立刻重连；之后每 30 秒自动重试一次，不用刷页面） |
| ⚪ 灰 | 还没检测（刚打开页面） |

想看细节就点徽章，或到面板里按 **检测连接** —— 它会一次报清三件事：
进程在不在、**模型加载完没有**、有多少个音色。

```
http://127.0.0.1:9880 在线 · 模型已加载（Natsume-e14.ckpt）· 14 个音色
http://127.0.0.1:9880 有响应，但模型还没加载完（engine_loaded=false）—— 再等十几秒
http://127.0.0.1:9880 连不上：Failed to fetch
```

> 「模型没加载完」和「进程没起来」在旧版里报的是同一句话，但处理方式完全不同，所以分开了。

**Q：她不出声。**
① 面板状态栏写什么？连不上会显示「连不上 TTS 服务」。
② 浏览器拦截自动播放：点一下页面任意处，或用消息上的 🔊 手动播。
③ 局域网设备上：TTS 服务必须是 `--host 0.0.0.0`（见 §2①）。
④ **跨源被拦（最隐蔽的一种，已修）**：酒馆是网页，扩展 fetch 的是另一个端口，
   浏览器会**先发 OPTIONS 预检**。服务端原来不认 OPTIONS，直接回 501 且不带 CORS 头 ——
   现象是「点播放完全没反应，服务端日志里连一条请求都没有」，因为请求根本没发出去。
   现在 `_send()`/`end_headers()` 统一带上 `Access-Control-Allow-*` 并实现了 `do_OPTIONS`。
   自检：

   ```bash
   curl -s -i -X OPTIONS http://127.0.0.1:9880/ -H "Origin: http://127.0.0.1:8000" \
        -H "Access-Control-Request-Method: POST" | head -3      # 应为 204 + Access-Control-Allow-Origin
   ```

   改完这个要**重启 TTS 服务**（`infer_api.py` 是常驻进程）。

**Q：她说中文 / 一次说一大段。**
模型没守协议。检查「API 连接」里模型是否够强（弱模型会忽略 system prompt），
或把 `post_history_instructions` 的提醒保留着（卡片自带）。

**Q：想让她说中文语音。**
服务端 `text_lang` 是逐请求参数，扩展写死 `ja`。改 `extension/index.js` 里 `synthesize()` 的
`text_lang` 即可；但**参考音频全是日文**，`prompt_lang` 不要跟着改成 zh，否则音质会掉。

**Q：声音都差不多。**
8 个基础角度指向的是**同一音色、不同语气**的参考片段。差别在语速/停顿/情绪色彩，不在音色——
这是 GPT-SoVITS 参考音频的作用方式。

**Q：改角色卡内容。**
改 `card/natsume.card.json` → 重新打包 → 重新导入：

```bash
cd $HOME/Code/Harness/Natsume_TTS/st-integration
python3 tools/make_card.py --spec card/natsume.card.json \
    --image $HOME/Code/Harness/Work/stellacafe-assets/card/natsume_avatar.png \
    --out card/四季夏目.png
```

**Q：改了扩展代码怎么生效。**
浏览器里刷新页面即可（酒馆扩展是每次加载页面时拉的）；不用重启酒馆。软链接指向本目录，改这里就是改那儿。
